# The Wall

Социальная сеть с одной общей бесконечной 2D-стеной. Любой может приклеить текстовый пост-стикер, перетащить его в любое место, нарисовать поверх стены стрелки и связи, а также занять приватный участок, где никто другой не сможет ничего менять.

Реализация сделана по документам «Бизнес-гипотеза (Lean Canvas)» и «Архитектура и техническое задание».

## Что реализовано

| Требование ТЗ | Реализация |
|---|---|
| Core №1: пост-стикер на бесконечной стене | `POST /posts`, `PATCH /posts/{id}`; стикеры двигаются мышью (drag-and-drop), стена панорамируется и масштабируется |
| Core №2: приватные участки | `POST /zones`; в чужой зоне нельзя создавать, двигать посты и рисовать; бесплатно — 1 000 000 px² на пользователя (freemium) |
| Core №3: рисование как в Paint | `POST /lines`; выбор цвета и толщины, кнопка «Отменить» |
| Анонимная регистрация | `POST /users` выдаёт ID и подписанный токен, без email и пароля |
| Текст ≤ 500 символов, ≤ 100 точек в линии | проверка на сервере и подсказки на клиенте |
| 10 постов в минуту с одного IP | ответ `429` |
| Фильтр мата | `app/profanity.py`, простой список корней |
| Last-write-wins | при одновременном перемещении побеждает последний запрос |
| Единый формат ошибок | `{"error": "...", "code": 400}` для 400/401/403/404/429/500 |
| Состояние сохраняется между сессиями | PostgreSQL на Render (SQLite при локальном запуске) |
| Временные сессии удаляются через 24 часа | анонимные пользователи, ничего не создавшие за сутки, удаляются фоновой задачей |
| Синхронизация без WebSocket | клиент опрашивает `GET /posts` раз в 5 секунд, ETag отдаёт `304`, если стена не менялась |
| Состояния интерфейса | спиннер загрузки, пост появляется сразу, ошибки — всплывающим сообщением внизу, пустая стена — «Стена пуста. Приклей первую идею!» |
| Производительность на 500+ постах | отрисовываются только видимые объекты, при отдалении текст заменяется штрихами |

Сверх ТЗ, но нужно для удобства: удаление своих постов, линий и зон; ссылка на конкретное место стены (`#x,y,масштаб` в адресе); горячие клавиши; жесты двумя пальцами на телефоне.

## Стек

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2, psycopg 3, Uvicorn.
- **База данных:** PostgreSQL (Render), SQLite для разработки.
- **Frontend:** HTML5 Canvas + Vanilla JS (ES-модули), без сборки и внешних библиотек.
- **Хостинг:** Render.com — один Web Service раздаёт и API, и клиент.

## Локальный запуск

Нужен Python 3.12+. В PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000 — это сама стена. Документация API (Swagger) — http://127.0.0.1:8000/docs.

Без переменной `DATABASE_URL` данные хранятся в файле `wall.db` рядом с проектом. Тесты запускаются командой `pytest`.

## Деплой на Render.com

### Вариант 1: Blueprint (рекомендуется)

1. Загрузите проект в репозиторий на GitHub (или GitLab).
2. В [Render Dashboard](https://dashboard.render.com) выберите **New → Blueprint** и укажите репозиторий.
3. Render прочитает `render.yaml` и создаст:
   - базу **the-wall-db** (PostgreSQL, бесплатный тариф);
   - веб-сервис **the-wall**, которому автоматически передадутся `DATABASE_URL` и случайный `SECRET_KEY`.
4. Нажмите **Apply** и дождитесь окончания сборки. Сайт будет доступен по адресу вида `https://the-wall-xxxx.onrender.com`.

Таблицы в базе создаются автоматически при первом запуске. Каждый push в основную ветку запускает новый деплой.

### Вариант 2: вручную

1. **New → PostgreSQL**: тариф Free, регион тот же, что будет у сервиса. После создания скопируйте **Internal Database URL**.
2. **New → Web Service** → репозиторий:
   - Runtime: **Python 3**
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   - Health Check Path: `/health`
3. В **Environment** добавьте:
   - `DATABASE_URL` — Internal Database URL из шага 1;
   - `SECRET_KEY` — любая длинная случайная строка;
   - `PYTHON_VERSION` — `3.12.6`.

### Особенности бесплатного тарифа

- Бесплатный веб-сервис засыпает после ~15 минут без запросов. Первое открытие после простоя занимает до минуты — на странице в это время показывается подсказка.
- Бесплатная база PostgreSQL на Render живёт ограниченное время (на момент подготовки — 30 дней) и одна на аккаунт. Актуальные условия смотрите в Dashboard; для постоянной работы нужен платный план (~$7/мес, как и заложено в бизнес-гипотезе).
- `SECRET_KEY` нельзя менять после запуска: по нему проверяются токены пользователей, и при смене все потеряют права на свои посты и зоны.
- Лимит «10 постов в минуту» считается по IP. Если на демонстрации все сидят в одной Wi-Fi-сети, временно увеличьте `MAX_POSTS_PER_MINUTE` в Environment.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./wall.db` | строка подключения; `postgres://…` от Render подходит как есть |
| `SECRET_KEY` | `dev-secret-change-me` | ключ подписи анонимных токенов |
| `MAX_POSTS_PER_MINUTE` | `10` | лимит постов с одного IP в минуту |
| `MAX_USERS_PER_MINUTE` | `30` | лимит регистраций с одного IP в минуту |
| `MAX_WALL_POSTS` | `1000` | максимум постов на стене |
| `MAX_WALL_LINES` | `1000` | максимум линий на стене |

Остальные константы (размер стикера, бесплатная площадь зоны и т. д.) — в `app/config.py`.

## API

Все ответы — JSON. Действия, меняющие стену, требуют заголовок `Authorization: Bearer <token>` из `POST /users`.

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/users` | анонимная регистрация → `{id, token, created_at}` |
| `GET` | `/posts` | вся стена: `{posts, lines, zones}`; у каждого объекта признак `is_mine` |
| `POST` | `/posts` | `{text, x, y}` → пост |
| `PATCH` | `/posts/{id}` | `{x, y}` → пост с новыми координатами |
| `DELETE` | `/posts/{id}` | удалить свой пост |
| `POST` | `/lines` | `{points: [[x, y], …], color, thickness}` → линия |
| `DELETE` | `/lines/{id}` | удалить свою линию |
| `POST` | `/zones` | `{x1, y1, x2, y2}` → зона |
| `DELETE` | `/zones/{id}` | удалить свою зону |
| `GET` | `/config` | ограничения для клиента |
| `GET` | `/health` | проверка работоспособности для Render |

Коды ошибок: `400` — невалидные данные, `401` — нет токена, `403` — чужая приватная зона или чужой объект, `404` — не найдено, `429` — слишком много запросов, `500` — внутренняя ошибка.
